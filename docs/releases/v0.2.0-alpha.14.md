# Chriz BG Modpack v0.2.0-alpha.14

## Fixes

- **Scrolls at the reader's level (430) stay on for the whole session.**
  Alpha.11 to alpha.13 turned themselves off after a load, a new game, an NPC
  joining or opening a container, showed an EEex message box, and scrolls then
  cast at their normal level until the game was restarted. A queued scroll cast
  now carries its reader with it, so this no longer happens. Saves made while
  430 was off or not installed now load without turning it off. See the
  [scroll casting guide](../scroll-casting.md).
- **Campaign XP banking (650): script variables survive saving and loading
  again.** When the bank could not take an XP change, alpha.11 to alpha.13
  stopped the game from processing the rest of that character's effects. Script
  variables set behind it went missing from saves and after loading
  ([chriz-bg-collection#19](https://github.com/Chrizhermann/chriz-bg-collection/issues/19)).
  Now such a change never holds up the other effects. See the
  [banking guide](../campaign-xp-banking.md).

## What you see in the game

Both components write technical information to the loader log only
(`InfinityLoader.log` in the game folder), not into the game.

- **430** shows one message box in one rare case: when it fails to start and
  cannot take all of its changes back out of the running game. The box appears
  while the game starts, before the main menu:

  ```text
  chriz-bg-modpack: scrolls at the reader's level could not start cleanly. Please quit and restart the game before you load or save a game.
  ```

  Loading or saving a game in that session is not safe, so quit and restart.
  Saves already on disk are not affected. This case was never seen in a game.
  In every other problem, 430 turns itself off for the session, scrolls cast at
  their normal level, saves stay usable, and only the loader log says so.
- **650** shows its startup failure and its fallbacks in the loader log only.
  `CBMBank_Status()` in the cheat console shows the reason on request. Cap and
  release messages still appear in the game as before.

## Rare cases accepted for this release

Banking (650) does not bank an XP change the normal way in these cases. The
loader log counts them once per loaded game.

- If the bank fails or refuses an XP change, the game applies it the usual way,
  as without 650. The cap still applies while the character's bank account is in
  order; if the account itself is at fault, that character's XP is not capped.
- While a save is written, or another XP change of the same character is in
  progress, the change waits for that character's next effect update.
- If the character's XP or the change itself changed while the bank prepared it,
  the bank tries once more, then applies it the usual way. No change waits for
  good.
- Only if the bank cannot withdraw what it had already recorded does the change
  end without XP. The amount is kept in the bank's unresolved journal, and that
  character is not capped from then on, also after saving and loading, until
  resolving such journals is implemented.
- If a character is created or destroyed outside the game's main thread, banking
  switches off for the rest of the session. Saves made after that keep characters
  with a bank account out of banking, also after a restart, so their XP is not
  capped. A static check of the game's threads found no way for this to happen,
  but it cannot rule one out.

Scrolls (430) have four known limitations, listed in the
[scroll casting guide](../scroll-casting.md#known-limitations). Three need a game
call on another thread at an exact moment and were never seen. In the fourth, a
saved scroll effect read by a creature outside the party turns 430 off for that
session if, after loading, the reader is not in a loaded area when the effect's
later part comes due.

## Install order

Unchanged from alpha.13:

- **430** after all spell and item changes. Reinstall it if those change later.
- **650** after EET finalization and the companion XP options you use
  (237/238/239/620), then **651** or **652**. Restart through InfinityLoader.

## Testing status

Automated: the full repository suite passes: 3,059 tests with real WeiDU 249,
including installer install/uninstall and the offline native checks. It skipped
457 checks: 433 need unbundled pinned game executables and pass when run with
them, 20 need a built release archive, and 4 need local game files. The built
release archive passes its own 20 checks.

In a game, on disposable lab installs of BG2:EE 2.7.3.0 with EET and EEex
v1.3.1:

- **430**, October 23 to 26, with Spell Revisions: scroll levels for active,
  non-caster and dormant dual-class readers; loading older saves, new games, NPCs
  joining, opening containers, area changes and scroll learning; saving and
  reloading during continuing scroll effects and queued scroll casts; saves made
  while 430 was off; a forced problem and a second load of the startup script,
  each with only the loader-log lines and no box. The guide records each build by
  its DLL hash.
- **650**, October 23 and 24, EET with only EEex and 650: two script variables set
  on the main character survived saves made while the bank was forced to refuse
  XP changes, in the same and in a new game process. Refused awards and
  `ChangeStat` changes were applied the usual way and still capped, and banking
  resumed afterwards.
- **The release candidate's package**, October 26, with 430, 650 and 651 on a
  copy of the collection's Recommended install: a normal start without a box;
  Imoen's Free Action scroll at level 4, half her level; a party award above the
  SoA cap banked. With the bank forced to refuse, the award was applied the
  usual way and still capped, the loader log got one line, and nothing appeared
  in the game. Two script variables set right after it survived a save made
  during the refusal, in the same and in a new game process, and banking
  resumed.

Not yet tested in a game: an ongoing playthrough with 430; with 650, manual
level-up and the dual-class pages, multiclass characters, the record-screen bank
display and chapters reached through the story.
